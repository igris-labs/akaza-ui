Use components for ready-made accessible behavior and composables when controls or state live elsewhere. Import these functions from `akaza-ui` in `<script setup>`.

| Composable | Use it for |
| --- | --- |
| [useColor](/composables/use-color) | Color values, output formats, and channel changes. |
| [useDataTable](/composables/use-data-table) | Table data, sorting, filtering, selection, pagination, and column state without a generated table. |
| [useDisclosure](/composables/use-disclosure) | Boolean open state with open, close, and toggle actions. |
| [useFormReset](/composables/use-form-reset) | Resetting custom state with a native form, respecting cancellation and form ownership. |
| [useOverlay](/composables/use-overlay) | Opening dialogs, drawers, and custom overlays programmatically, including a close result. |
| [useSidebar](/composables/use-sidebar) | Controlling a particular Sidebar or connecting application-owned responsive state. |
| [useToast](/composables/use-toast) | Adding, updating, and dismissing notifications, including promise results and scoped managers. |
| [useTypeahead](/composables/use-typeahead) | Buffered keyboard text with timeout and optional repeated-character cycling. |

`createToastManager` and `provideToastManager` are documented with [useToast](/composables/use-toast#scoped-managers).

## Components and composables

A composable does not render DOM or accept `ui` classes. Its associated component owns the markup, styling hooks, focus behavior, and keyboard interaction. `useDataTable` can also power a custom native table; in that case, you own the rendered semantics and controls.

The Nuxt module auto-registers components only. Use explicit imports for composables to avoid collisions with Nuxt UI or application functions such as `useToast`.

## Reactive inputs

Pass refs or getters when an option supports them. Passing `data.value` gives a composable the current array, not future replacements; pass `data` or `() => data.value` instead. Each page identifies which options are reactive.

## SSR and scope

Call `useOverlay()` and the default `useToast()` in component setup. Their server state belongs to the current Vue app, not the server process. Capture the manager in setup for later event handlers. For separate notification queues, create and provide a toast manager inside the owning component.

Only package-root exports are public. Internal helpers such as `useDialog` and `useTooltip` are not supported imports; use the corresponding component's slots or template ref. Shared positioning, field registration, focus traversal, and delay helpers remain internal: they implement individual mechanics, not a complete accessible control.
