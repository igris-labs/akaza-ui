`Select` renders a trigger and a `role="listbox"` popup. It supports single or multiple values, grouped options, typeahead, cancelable changes, and [Field](/components/field) metadata.

Popup placement flips when preferred side lacks room, clamps to viewport, and follows anchor/content resize and ancestor scrolling.

The popup uses the browser's native top layer when available, including when rendered inline. `teleport` controls its DOM parent; inline rendering remains the default. The hidden native select stays in the field's form.

`open-change` can cancel any opening or dismissal request. A controlled parent that refuses the update keeps the popup interactive, preserves focus, and does not mark its content inert. Focus returns after an accepted selection or Escape close, not after an outside press.

Use `autocomplete` to filter the list. Use [Combobox](/components/combobox) when the text input is the main control.

## Anatomy

- **`#trigger`**: Custom trigger content. Use `triggerProps` when rendering your own interactive trigger.
- **`#value`**: Selected value content inside the trigger.
- **`#option`**: Content inside each generated `role="option"` row.
- **`#group-label`**: Content for non-selectable label rows.

The trigger, listbox, options, indicator, separators, and hidden native select are generated by the component. Style those generated parts with the matching `ui` keys.

## Usage

::

::component-code
```vue
<script setup lang="ts">
import { Select } from "akaza-ui";
import { ref } from "vue";

const plan = ref("pro");
const options = [
  { value: "free", label: "Free" },
  { value: "pro", label: "Pro" },
  { value: "team", label: "Team", disabled: true },
];
</script>

<template>
  <Select
    v-model="plan"
    :options="options"
    placeholder="Choose plan"
  />
</template>
```

## Examples

### Inside a scrolling dialog

Teleport the options to `body` to let them extend outside the dialog's scrollable body. The native select stays in the form, and the popup stays inside the dialog's focus scope.

::component-preview
  :::examples-select-portal
  :::
::

::component-code
```vue
<script setup lang="ts">
import { Dialog, Select } from "akaza-ui";
import { ref } from "vue";

const open = ref(false);
const project = ref("alpha");
const projects = [
  { value: "alpha", label: "Alpha" },
  { value: "beta", label: "Beta" },
];
</script>

<template>
  <Dialog
    v-model="open"
    title="Project details"
  >
    <template #trigger="{ toggle }">
      <button @click="toggle">Open project dialog</button>
    </template>
    <template #body>
      <Select
        v-model="project"
        :options="projects"
        teleport="body"
        name="project"
        aria-label="Project"
      />
    </template>
  </Dialog>
</template>
```
::

Use a CSS selector for another portal target, or `:teleport="false"` to keep the popup inline. The target must exist when the popup renders. Inline and portaled options use fixed positioning and keep the trigger's width, limited to the available space. Native top-layer presentation escapes clipping without changing the DOM parent; a portal also avoids clipping in the fallback presentation.

Style portaled options through `ui.content`, `ui.option`, and the other popup parts. CSS selectors scoped beneath the Select root do not reach a portaled popup. Tab and Shift+Tab close a portaled search and continue from the trigger's position in the page.

### Multiple selection

Multiple selection toggles one value without dropping other selected values, including disabled or currently filtered-out options. Option values are normalized to strings; use Listbox or Combobox when numeric and string identity must remain distinct. Native form submission includes each selected enabled option under the same field name.

Set `multiple` and bind `v-model` to `string[]`. Selected options stay open so users can toggle more than one item.

```vue
<script setup lang="ts">
import { ref } from "vue";
import { Select } from "akaza-ui";

const permissions = ref(["read"]);
const options = [
  { value: "read", label: "Read" },
  { value: "write", label: "Write" },
  { value: "deploy", label: "Deploy" },
];
</script>

<template>
  <Select
    v-model="permissions"
    multiple
    :options="options"
  />
</template>
```

### Grouped options

Use `type: "label"` and `type: "separator"` for non-selectable rows. They are skipped by keyboard navigation.

```vue
<template>
  <Select
    v-model="role"
    :options="[
      { type: 'label', label: 'Project' },
      { value: 'viewer', label: 'Viewer' },
      { value: 'editor', label: 'Editor' },
      { type: 'separator' },
      { type: 'label', label: 'Admin' },
      { value: 'owner', label: 'Owner' },
    ]"
  />
</template>
```

### Autocomplete filtering

Set `autocomplete` to render a search input inside the popup. Focus moves into the search input when opened; that input owns `aria-activedescendant` and Arrow/Enter/Escape navigation. Bind `v-model:search` when search text should drive async loading or external filtering.

```vue
<script setup lang="ts">
import { ref } from "vue";

const value = ref("");
const search = ref("");
</script>

<template>
  <Select
    v-model="value"
    v-model:search="search"
    autocomplete
    :options="options"
    search-placeholder="Filter options"
  />
</template>
```

### Field integration

Place `Select` inside [Field](/components/field) to inherit `id`, `name`, `required`, disabled state, invalid state, and `aria-describedby`. Required/native invalid state is revealed after selection, blur, or invalid submit; it is not shown on initial render.

```vue
<template>
  <Field
    label="Server region"
    name="region"
    required
  >
    <Select
      v-model="region"
      :options="regions"
      placeholder="Choose region"
    />
  </Field>
</template>
```

### Custom option row

Use `#option` to render richer option content. The component still owns `role="option"`, selection state, highlighting, and click handling.

```vue
<template>
  <Select
    v-model="region"
    :options="regions"
  >
    <template #option="{ label, description, isSelected }">
      <span aria-hidden="true">{{ isSelected ? "✓" : "" }}</span>
      <span>
        <strong>{{ label }}</strong>
        <small>{{ description }}</small>
      </span>
    </template>
  </Select>
</template>
```

### Cancel a selection

`value-change` fires before the model changes. Call `details.cancel()` to block a value.

```vue
<template>
  <Select
    v-model="role"
    :options="roles"
    @value-change="(value, details) => value === 'owner' && details.cancel()"
  />
</template>
```

## Replacing suggestions

Autocomplete results may change while the popup is open. The active option follows its value when results are reordered; removing it falls back to the first enabled result, or clears the active target when none remain. Enter does not activate a missing, disabled, or loading option. IME confirmation in the search input does not select prematurely.

### Native Form Reset

A native form reset restores the initial model and clears interaction state. Calling `preventDefault()` on the reset event preserves the current value. Reset updates `v-model` without emitting `value-change`.

Plain `class` applies to the root wrapper. Use `ui.trigger`, `ui.content`, and `ui.option` for internal parts.

Popup transitions follow their placement side and last `120ms`. Set `--akaza-select-duration` to change the duration. Reduced-motion mode removes the visible transition.

Native `data-akaza-invalid` appears after interaction or invalid submit. Controlled invalid state from the `invalid` prop or parent `Field` appears immediately.

### Keyboard

Type on the focused trigger to highlight an enabled option without selecting it. Matching ignores case and accents. Repeat a letter to cycle matches; the query clears after 500ms. Space continues an active query, otherwise it opens the list or selects the highlighted option. Autocomplete text uses the search input instead.

Using the popup scrollbar or mouse wheel keeps the list open. After a scrollbar gesture moves focus away, focus returns to the trigger, or to the search input when autocomplete is enabled. Moving focus to an outside control or clicking outside still closes the popup.

Opening with an arrow highlights the selected enabled option, or the first enabled result. Subsequent arrows move highlight without selecting. Set `:loop="false"` to stop at either edge. Home and End target the first and last enabled result, including when opening from the trigger. Only the options viewport scrolls.

Navigation and activation ignore prevented events, IME composition (including legacy key code 229), and Ctrl/Meta/Alt combinations. Disabled native fieldsets also block these actions. Search and open requests must be accepted before they can replace the active target.

| Key | Behavior |
|-----|----------|
| `Enter` / `Space` | Open select, or select/toggle highlighted option. |
| `ArrowDown` / `ArrowUp` | Open at selected/first enabled option; move highlight when open. |
| `Home` / `End` | Move highlight to first/last enabled option. |
| `Escape` | Close popup. |
| printable character | Typeahead to matching option label. |
